### Notes and deviations
- Phases were renumbered 0–8 → 1–9 so the progress script can count them.
- **Research pass, 2026-10-05** (desk research done before anything was run, so every number in this block is a claim from a doc or release note. **Where a measurement further down says otherwise, the measurement wins**: for example Godot is now installed on the PC, the JSON-schema route turned out to be unsafe, and the Windows voices and the speed estimates were measured):
  - **Versions.** Godot 4.7 shipped in June 2026 and 4.7.1 on 2026-07-14. NobodyWho's `main` declares `compatibility_minimum = 4.6` with no maximum, so it should load on 4.7.x. godot-whisper v2.0.2 (2026-05-19) is titled "Fix for godot 4.7". The plan's "both list 4.3 as the minimum" is out of date.
  - **NobodyWho moves fast.** Godot plugin v9.3.0 (2026-05-18) → v11.0.0 (2026-09-10), with breaking changes in v10 (STT/TTS nodes renamed to `NobodyWhoSpeechToText` / `NobodyWhoTextToSpeech`) and v11 (system prompt moved to a node setting, media moved into message content). Pin the version we install and record it in `docs/measurements.md`.
  - **NobodyWho now bundles more than the LLM:** speech-to-text (Whisper ONNX, `transcribe_pcm`, streaming `transcription_updated`), text-to-speech (Kokoro, Supertonic, Pocket TTS) and voice activity detection (Silero). So it could replace godot-whisper and possibly the OS voices. TTS is **not streaming** (`await tts.synthesize(text)` returns a whole WAV). No voice cloning is documented for it. Pocket TTS lists English and French only.
  - **Structured output** has presets: `set_sampler_preset_constrain_with_json_schema()`, `..._with_grammar()` (GBNF), `..._with_regex()` and `set_sampler_preset_json()`. Streaming is the `response_updated(token)` signal. `context_length` defaults to **4096**, which the boss-review prompt may exceed.
  - **Thinking models.** Qwen3-style models start with `<think>`, which fights a grammar. Release 9.6.0 fixed a silent crash when a thinking model met a grammar. Prefer a non-thinking model or switch thinking off, and test it.
  - **Field order matters.** Put `say` first in the JSON so TTS can start before `suspicion` and `action` are generated.
  - **GPU.** macOS uses Metal. Windows and Linux need a Vulkan driver and fall back to CPU without one. Memory rule of thumb: about 1.5× the model file in free RAM. The `use_gpu_if_available` property is on the model node.
  - **Models.** Gemma 4 (April 2026; sizes E2B, E4B, 12B, 26B-A4B, 31B) and Qwen3.5 (March 2026; 0.8B, 2B, 4B, 9B) are both **Apache 2.0**, so bundling is legally simple. Qwen3.5 thinks by default.
  - **OS voices on Windows.** `DisplayServer.tts_speak` uses the older SAPI path and probably cannot see Windows 11's newer "natural" voices. It has no completion callback in the docs and gives "delays when you call `tts_speak`". The plan's "free, native and robotic fits the comedy" may be fine on Mac and weaker on Windows. Measure it.
  - **The reference game** (*Scam With Your Friends*) runs its AI in the cloud (OpenRouter), needs internet, is Windows-only, and has an optional $8 "Unlimited AI" purchase in its playtest. Early Access is October 2026, full release mid-December. Our local-first, no-running-cost design is the difference, and the quality gap to a cloud model is the risk.
  - **Licences.** NobodyWho is EUPL-1.2 (copyleft; its README says commercial use is fine, but get it checked before Phase 9). godot-whisper is MIT.
  - **Machines.** The Mac (M4) and the Windows PC (i5-13400F, 32 GB RAM, RTX 3070 with 8 GB VRAM) are both in use. CLAUDE.md's verify command is the Mac path only. Godot was not installed on the PC at that point (it is now).
  - **Performance estimate (not a measurement).** A base M4 has about 120 GB/s of memory bandwidth, so a 4B Q4 model should generate roughly 25–35 tokens per second. A reply plus JSON keys is about 60–80 tokens, so about 2–3 s. The "under 2 seconds" exit criterion is tight there.
  - **Sources:** NobodyWho repo, releases and docs (docs.nobodywho.ooo/godot), godot-whisper releases, Godot TTS docs, Steam store page, Godot 4.7.1 release post.
- **Findings from the first runs, 2026-10-05** (these are measured or seen, not claimed):
  - **Addon binaries cannot be committed to GitHub.** NobodyWho's Windows DLL is 141 MB, its macOS libraries 94–103 MB and its Linux ones 129–132 MB; GitHub rejects files over 100 MB. So `addons/**/bin` and the NobodyWho libraries are git-ignored and fetched by `scripts/setup_addons.py`, which pins both versions by SHA-256 and unpacks only the current OS's libraries. The small addon files (`.gdextension`, scripts, licences) are tracked. Phase 9 should keep this in mind: shipping on Steam is unaffected, because Steam has no such limit.
  - **Godot hangs at exit on this Windows PC when its output is redirected** by the shell (`> file`, a pipe, or PowerShell's `-RedirectStandardOutput`). It runs fine with `--log-file`. `scripts/godot_run.py` handles this, picks the right binary on Windows or macOS, and prints the log; use it instead of calling Godot directly. A fresh `--import` is needed after adding `class_name` scripts (`--import` flag on the wrapper).
  - **API as installed (v11.0.0).** `NobodyWhoChat` has `allow_thinking` (so thinking can be switched off), `system_prompt`, `context_length`, `say()`/`ask()`, `reset_context()`, `get_stats()`, the signals `response_updated`, `response_finished`, `worker_started`, `worker_failed`, and the sampler presets listed in the research notes. `NobodyWhoTextToSpeech` has `synthesize()` and a `synthesis_finished(wav)` signal. `NobodyWhoVoiceActivityDetection` has `push()`, `finish()` and the signals `speech_started` / `speech_ended`.
  - Godot 4.7.1 is installed in `.tools/godot/` (SHA-512 checked) and `models/` holds the downloaded GGUF files (git-ignored; `models/.gdignore` stops Godot scanning them).
- **Low-end options, measured on the Windows PC with the director on (`docs/measurements.md`):** **Gemma 4 E2B Q4_K_M** (3.1 GB, 2.3B effective parameters) on the GPU replies in a median 0.48 s (p95 0.97 s) at 107 tokens per second, needs only +2.0 GB VRAM and 2.0 GB RAM, gives 100% valid replies and obeys every director order (pay 8/8, stall 41/41). Its lines are decent but blander than E4B's, and it often starts the spoken line with a stray `:` (now stripped by `ReplyParser.clean_say`). **With no GPU at all** (CPU only, 10 cores): E2B takes a median 2.1 s (p95 2.9 s, 28 tokens per second) and E4B 3.8 s (p95 4.4 s, 17 tokens per second), so a PC without a usable GPU should get E2B. These CPU runs were 3 calls each (15 turns), so they are indicative, not tight. Recommended low-end setting for Phase 9: E2B, on the GPU if there is one, else on the CPU.
- **Measured on the Windows PC (RTX 3070 8 GB, i5-13400F), 2026-10-05.** Raw data is in `docs/runs/`, the table in `docs/measurements.md`:
  - **The JSON-schema constraint is not safe enough.** It lets the model choose any key order and emit unlimited whitespace. A Gemma 4 reply started with `{"action": "talk", "amount": 0, "say": ...` and then produced 3,420 tokens of newlines until the 45 s timeout (it repeated on the second run). The fix is a **GBNF grammar** (`ReplyParser.grammar_for()`): fixed key order, no whitespace outside the spoken text, `say` capped at 300 characters. NobodyWho converts it to a Lark grammar internally and accepts it. With it, replies were 100% valid on Qwen and Gemma, about 20% shorter (37 vs 55 tokens, so 773 vs 904 ms median on Qwen), and `say` is always first. `CallerBrain` also cuts a turn off at 220 tokens (`MAX_REPLY_TOKENS`) as a second safety net.
  - **Speed is not the problem on a mid-range GPU.** Qwen3.5-4B Q4_K_M: about 80–88 tokens per second, median reply 0.8–0.9 s, p95 1.2 s, model load 2 s warm, +3.3 GB VRAM, 3.4 GB RAM. Gemma 4 E4B Q4_K_M: about 70–77 tokens per second, median reply 0.7–0.8 s, +3.6 GB VRAM. Prefix caching works: on a warm turn the first token arrives in about 45 ms (Gemma) or 250 ms (Qwen). On **CPU only** (no GPU) the same Qwen 4B model does 14 tokens per second and a median reply takes 5.2 s, which is the low-end setting's real cost.
  - **Cold loads are slow on this machine's data drive.** The `G:` drive is a 5400 rpm HDD: first loads took 53–87 s for 2.7–5 GB models (about 50–70 MB/s), warm loads 2–3 s. Players on an SSD will see the warm figure; the game still needs a loading screen and a "model is loading" state.
  - **Replies are deterministic.** NobodyWho's default sampler uses seed 1234 and temperature 0.6, so the same line to the same persona gives the same answer. With real speech that rarely matters. The sampler builder on NobodyWho's `main` branch has `json_schema()`, `lark()` and `seed()` steps, but the released v11.0.0 does not, so seed and temperature cannot be tuned together with the grammar until the next release. Variety has to come from the prompt (moods, events) for now.
  - **A GPU load failed three times at random** (generic "could not load the model" error) and then worked in 12 of 12 later runs with the same file; the cause is unknown. `LlmService` now retries on the CPU if a GPU load fails, so a call never dies on it. A separate, understood failure: on an 8 GB card the 8B model leaves no room for a second chat context while the first is still being released (`Could not create context`). `LlmService` waits and retries once.
  - **Quality differs a lot between models.** From the transcripts, Gemma 4 E4B is clearly funnier and more coherent in character than Qwen3.5-4B (Qwen produced lines like "the front of my cat" and repeated a reply word for word). Gemma also lets suspicion move over a call; Qwen's barely moves. This is my reading, to be confirmed by the user's fun check.
  - **Payment is the weak point, and a prompt alone does not fix it.** With the first prompt (12 calls of up to 6 turns, grammar on) the models said they were paying but reported `action: talk` (15 such mismatches on Qwen, 4 on Gemma: Gladys reads out digits, Barry says "sending the money over now"). A second rules file (`data/caller_rules_v2.txt`: explicit payment protocol and format examples) plus the key order `say, action, amount, suspicion` (`--order=action_first`) cut Qwen's mismatches to 0 and raised its paying calls from 3/12 to 5/12, but **Gemma paid in 0 or 1 of 12 calls** whatever the prompt: its alignment makes it stall and then hang up on a gullible old lady ("I really can't give out banking information"). Ministral 8B paid in 4–7 of 12 but with 6–10 mismatches. So how often a caller pays cannot be left to the model.
  - **Decision: the game directs, the model acts** (`src/call_director.gd`). Every turn the code works out whether the caller is persuaded (from gullibility, suspicion and how long the call has run) and appends a private `[DIRECTOR: ...]` note to the player's line: stay in the scene, too early, stall, **pay** (with a price cap), or hang up. With the refined director both Qwen and Gemma obeyed **every** order (Gemma: pay 8/8, stall 41/41; Qwen: pay 7/7, stall 42/42), there were 0 payment mismatches, and the pay rate is now a number we set: a unit test over 3,000 simulated calls gives Gladys 93%, Barry 37%, a scambaiter 10% of calls ending in a payment. This also makes balancing the quota in Phase 4 a matter of changing numbers, not prompts.
  - **Model decision: Gemma 4 E4B Q4_K_M** (`gemma-4-E4B-it-Q4_K_M.gguf`, 4.98 GB, Apache 2.0) with `data/caller_rules_v3.txt`, the grammar, the key order `say, action, amount, suspicion` and the director. On the Windows PC: median reply 0.72 s (p95 1.2 s), the spoken line is complete at a median 0.52 s, 72 tokens per second, 100% valid replies, +3.6 GB VRAM and 3.6 GB RAM, warm load 2.2 s. It is the most fluent and the funniest of the three in the transcripts (my reading; the fun check is the user's). Qwen3.5-4B generates tokens about 15% faster (83 vs 72 per second) but its replies run longer, so a whole reply takes more time (median 0.89 s), it is slightly smaller (2.74 GB), and its lines are weaker and sometimes incoherent, so it is the fallback. Ministral-3 8B is too slow for the 2 s target on this card (median 1.5–1.8 s, p95 up to 2.1 s), needs +5.4 GB VRAM, and twice failed to create a second chat context on an 8 GB card, so it is not recommended.

### Notes and deviations
- **Phase 2 notes, 2026-10-05.** What changed in the prompt and the code, and why (numbers are in `docs/measurements.md`):
  - **Prompt v1 → v2 → v3.** v1 (`caller_rules.txt`) had no payment rules. v2 added an explicit payment protocol and three format examples. v3 (`caller_rules_v3.txt`, the one the game uses) replaces the payment rules with "obey the `[DIRECTOR: ...]` note on the player's line". v1 and v2 are kept so the table rows that used them can be repeated.
  - **JSON schema → grammar**, and **key order `say, action, amount, suspicion`**: see the Phase 1 notes. The grammar is the fix for runaway whitespace; the order puts the decision right after the line it belongs to.
  - **The director** (`src/call_director.gd`) is the biggest change: payments are decided by code, the model only writes the line. Without it Gemma never paid.
  - **Reply cleaning:** the model sometimes puts `*emphasis*` asterisks in the spoken text; a voice would read them out. `ReplyParser.clean_say` strips them (3 of 87 playtest lines).
  - **What did not work:** asking the model to decide when to pay (any prompt); the JSON schema (runaway replies); a free-form scammer ask for the card on turn 4 of 4 (nobody pays that fast; closing lines at turns 5 and 6 are in the test script).
  - **Known gap:** the playtest scammer is a bot, so its pitches are more repetitive than a human's would be. The first real human round is the user's.

### Notes and deviations
- **Findings from the voice test, 2026-10-05** (`scenes/voice_test.tscn`, raw data in `docs/runs/voice/`):
  - **godot-whisper vs NobodyWho Whisper:** equally accurate, godot-whisper is about 3.6× faster (146 vs 531 ms median, real-time factor 0.028 vs 0.106). godot-whisper's first call took 4.9 s (warm-up), so run a dummy transcription at start-up. NobodyWho's STT needs a 210 MB ONNX download at first run (9.5 s load once cached). godot-whisper also ships a ready-made microphone node (`CaptureStreamToText`, with voice detection) and prints a harmless "Unsupported GPU" error on this machine (it runs on the CPU). Both fit easily in the 3 s budget; godot-whisper stays the plan's choice, NobodyWho STT is the single-addon alternative.
  - **Windows OS voices are thin:** only Microsoft David, Mark and Zira (all US English) are installed, so Gladys's `en-GB` falls back to a US voice and three personas share three voices. They start speaking after about 62 ms, but they speak slowly (a 13-word line takes about 6.4 s; Kokoro says the same line in about 5 s).
  - **Kokoro through NobodyWho** gives British and American voices and is 7× faster than real time (steady state), but it returns the whole clip (no streaming), so the caller starts talking only after synthesis: about 0.4–0.95 s per line on top of the AI's 0.5 s. It adds a 326 MB model download (about 107 s to download and load the first time). I cannot judge how it sounds; the clips are in `.tools/voice/` for the user to listen to.
  - **ONNX Runtime logged a failed CUDA provider registration** and fell back to the CPU for Kokoro and Whisper. That is fine for speed here, and it keeps the GPU free for the language model.
  - **The first Kokoro version missed the budget on long lines** (median 2.77 s, worst 3.06 s) because it synthesized the whole line before playing anything, and because converting every sample in GDScript wasted time. Two fixes cut it to 1.14 s median, worst 1.45 s: the line is spoken sentence by sentence (the first sentence plays while the next is synthesized; sentences over 10 words are split at a comma), and 16-bit mono audio is used as it is. Speaking as soon as the spoken line is complete, instead of waiting for the action and suspicion fields, saves another 0.5–0.65 s.
  - **The first godot-whisper transcription on a fresh machine took 4.9 s** (probably driver or OpenCL start-up), but only 0.3 s in later processes, including a warm-up call at start-up (`VoiceInput.setup`). Expect a slow first launch.
  - **Voices cannot be judged by me.** I measured speed and intelligibility only. The 8 Kokoro clips are in `.tools/voice/tts_*.wav` (Kokoro `bf_emma`); the OS voices are David, Mark and Zira.

### Notes and deviations
- **Balance notes (estimates, 2026-10-05).** The pay odds are set by the director: over a typical call (three asks for money) Gladys pays in about 93% of calls, Barry 37%, a scambaiter 10%, so about 47% across the three starters (unit test over 3,000 simulated calls). A human call of about 10 turns at roughly 10 s a turn takes about 100 s, so a day holds about 4–5 calls and 2–2.5 paid ones. At an average price of $300 that is about $600–700 a day against a day-1 quota of $400 (1.5–1.7×), about $700 on day 5 (quota $700: break-even), and about $1,050 on day 8 (quota $1,050 needs about $450 a sale). So days 1–4 are comfortable, from day 5 the player must charge more or pick on the gullible callers, and from day 8 or 9 a bad run starts costing strikes. The caps are not the limit: Gladys $3,500, Barry about $5,200 at day-1 savings. Callers also get 0.015 harder to fool each day. These are numbers to tune by playing, in `GameState` (`QUOTA_FIRST_DAY`, `QUOTA_GROWTH`, `SHIFT_SECONDS`) and `CallQueue` (`HARDER_PER_DAY`). The bot-driven days are not a guide: the bot takes about 10 calls in 90 s and earns $1,000+ a day.
- **Rules I fixed while building it** (the plan did not say): a strike is only added when the quota is missed, and a pass does not remove one (three misses in total, not three in a row); the day advances either way; a call in progress when the clock runs out may finish, for up to 60 s, so a sale is not thrown away; clocking out early with too little cash is a missed quota; a failed model load is not counted as a call; being fired is reset by pressing New game, and the best day survives as a record; the caller's savings and gullibility vary per call (0.5–1.5× savings, ±0.1 gullibility).
- **The boss needed the game to do the judging.** First version: the model got the numbers and said "you barely scraped by" for $1,138 against a $400 quota, and read "$450" as "forty dollars". Fixes (all in `Boss.facts`): a performance word worked out by the game (outstanding, good, just enough, poor, disastrous, from cash divided by quota), a direct "Your tone: ..." line for each, and every amount also written in words. After that the tone matches the tier in all six test days (`docs/playtests/2026-10-05_boss-reviews.md`), with one slip left: the "fired" rant still called a $120 day "barely scraped by". Small-model noise; a person should judge whether it is funny.
- **The desk's button flow is tested end to end** (`scenes/desk_flow_test.tscn`, 39 checks on the real model, nothing typed by hand: every step presses a button): new game, clock in, answer, speak, hang up, answer again, clock out in the middle of a call, the review, day 2 with the higher quota, clock in and out to three strikes, being fired, New game, and a stray double press. It found three real problems, now fixed and covered: (1) a **double click on Clock in clocked you straight out again** (the button toggles) and cost a strike, so Clock out is ignored for the first 1.5 s; (2) pressing the clock button **while the boss review was being written** started a second shift whose object the first shift's "ended" handler then freed, so the desk now ignores the button during the review and each handler frees only its own shift; (3) the suspicion meter kept the last call's value on the review screen. It also found that a script **parse error makes Godot idle instead of exiting** (a 10-minute wait for me), so `scripts/godot_run.py` now stops at once when it sees "Failed to load script". One name clash worth knowing: a member called `_input` in a Control shadows Godot's own `_input()` method from outside, so the desk's text box is `_line_edit`.
- **All the tests together** (`python scripts/run_tests.py --full`, 2026-10-05 04:15): 14 tests and about 425 checks, all passing: 9 that need no model (4 s in total) and 5 on the real model (about 3.5 minutes).
- **The player's "best line" is the last thing said before the biggest payment, and the "worst line" the last thing said before a caller hung up.** They come from `CallSession.log`, which holds only the words that were spoken (the brain's own history includes the director's private notes).

### Notes and deviations
- **Why download on first launch and not bundle.** The main model is 5.0 GB and the small one 3.1 GB; players need only one of them, which depends on their hardware, so bundling would make every player download 3-5 GB they may not use and would make the Steam build large for everyone. NobodyWho downloads a model from Hugging Face by itself the first time it is loaded and keeps it in its own cache folder (`%LOCALAPPDATA%\nobodywho\models\` on Windows). The game then remembers the cached file's path, so later launches load it as a plain file (and the GPU-to-CPU fallback still applies). **Risk to decide on before release:** this depends on Hugging Face and NobodyWho's repositories staying available. The game does not use it. The supported route is to give a `NobodyWhoModel` a path of the form `hf:owner/repo/file.gguf` (the `hf:owner/repo:QUANT` form in NobodyWho's README is wrong for the Godot plugin and fails with "Failed parsing model path") and connect its `download_progress` signal; the model is downloaded when the first chat starts. `LlmService` does this and waits up to an hour for a first download (a normal load waits 3 minutes).
